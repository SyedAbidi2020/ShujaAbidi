Phase 2

Learning from the checker's feedback

After Phase 1 the model could explain errors in a given plan, but couldn't fix its own. In Phase 2 it writes plans, the checker grades every step and every state it claims, and the model trains on what the checker says.

1

The loop

Write, grade, learn, repeated 20 times on fresh problems.

The checker catches three kinds of mistake: an action whose preconditions are false, a claimed state that is wrong (the model applied the effects incorrectly even though the action was legal), and a goal that isn't reached.

2

What the feedback looks like

The same style of report as VAL, the standard plan validator.

Suppose that on the tower problem (goal: b on c on a) the model writes (pick-up c) (stack c a) (stack b c), forgetting to pick up b. The feedback prompt it gets back:

[INSTRUCTION] You previously generated a plan with step-by-step reasoning.
The validator has provided feedback on your reasoning. Use this feedback to
generate a corrected plan with improved logical reasoning.

[DOMAIN] ...   [PROBLEM] ...

[PREVIOUS PLAN]
Step 1: (pick-up c) - VALID
Step 2: (stack c a) - VALID
Step 3: (stack b c) - INVALID

[VAL FEEDBACK]
Plan Validation details
-----------------------
Checking next happening (time 1)
Deleting (ontable c)
Deleting (clear c)
Deleting (handempty)
Adding (holding c)

Checking next happening (time 2)
Deleting (holding c)
Deleting (clear a)
Adding (clear c)
Adding (handempty)
Adding (on c a)

Checking next happening (time 3)
Plan failed because of unsatisfied precondition in:
(stack b c)
Plan failed to execute

Plan Repair Advice:

(stack b c) has an unsatisfied precondition at time 3
(Set (holding b) to true)

[STEP BY STEP PLANNING]

3

Building the repaired answer

Keep what the model got right, finish with the planner, let the checker write the reasoning.

  1. Keep the model's valid steps. Here, (pick-up c) (stack c a) are both legal, so they stay. The model learns that its first steps were fine.
  2. Finish with A*. From the state reached after those steps, the planner finds the shortest way to the goal: (pick-up b) (stack b c). If keeping the model's steps would make the plan much longer than the shortest one, the shortest plan is used instead.
  3. Write the reasoning exactly. The checker writes the full step-by-step answer for the repaired plan, with every state correct, ending in [FINAL PLAN] (pick-up c), (stack c a), (pick-up b), (stack b c).
  4. Make two examples. The feedback prompt above with the repaired answer teaches how to use feedback. The plain planning prompt with the repaired answer teaches how to get it right first time.

4

Two stages

First train on the whole reasoning chain; then also stress the final plan.

Stage 1: iterations 1–10

The loss covers the whole answer: every precondition check, effect and state. About 30 training examples per iteration.

Stage 2: iterations 11–20

The same, plus an extra copy of each example whose loss covers only the [FINAL PLAN] line, so getting the plan itself right counts more. About 58 examples per iteration.

Where this differs from the paper: the paper describes a reasoning loss based on the difference between the claimed and true states, and a separate plan loss. As written, the state-difference loss can't be trained by gradient descent (counting differing facts is not differentiable), and no code was released. This rebuild uses the practical version above: ordinary token loss on checker-written answers, with the extra plan-only copy in stage 2.

5

The training run

20 iterations × 16 problems, one update each: about 3 hours.

Valid plans per iteration (out of 16, sampled)

Stage 1 averaged 1.7 valid plans out of 16, stage 2 about 2.6. These are noisy because each iteration sees only 16 new problems, written with randomness. What matters is the effect on the test set, below. The run used the same 8 GB laptop GPU; an out-of-memory crash in iteration 10 was fixed (clearing GPU memory after each example) and the run resumed from the saved iteration 9.

6

Testing with feedback rounds

At test time the model gets up to three chances, each with the checker's feedback on its last plan.

Valid plans after each feedback round (greedy decoding)

The first round of feedback nearly doubles the Blocksworld score (24% → 43%), so Phase 2 did teach the model to use the checker's report. After Phase 1, the same feedback fixed nothing. Later rounds help less, partly because with greedy decoding the model often repeats the same wrong plan. Sampling with some randomness in rounds 2 and 3 breaks those loops and lifts Mystery from 19% to 26% (total 71 of 200). See Results.
